# Systematic Literature Review (SLR) Agentic Workflow

This implementation plan outlines the setup and architecture for the semi-automated agentic workflow for a systematic literature review process.

## Architecture Decisions
- **Web Framework**: FastAPI (Python backend) with a React frontend.
- **Agent Framework**: **LangChain** will be used for all agent implementations. This provides a unified interface across different LLMs and easy extensibility for future complex tasks like RAG.
- **Data Format (Papers)**: One JSON file per database (e.g., `ieee.json`, `acm.json`).
- **Data Format (Metadata)**: **JSON** (`context/metadata.json`). JSON natively supports structured data and easily stores the raw keyword string alongside the compiled regex patterns generated by the Highlighting Agent.
- **Python Environment**: Using the existing `.venv`. All backend commands will use `./.venv/bin/python` and `./.venv/bin/pip`.

## Proposed Changes

### 1. Project Setup and Environment
- **Folder Structure**:
  - `context/`: For storing `metadata.json` (research questions, criteria, keyword strings, databases, and LLM mapping).
  - `agents/`: Each agent resides in a separate file using LangChain wrappers:
    - `agents/keyword_highlighter.py`
    - `agents/deduplication.py`
    - `agents/abstract_title_screening.py`
  - `data/`: Root directory for storing data across different SLR steps.
- **Environment Variables**: Create `.env` and `.env.example` files to store API keys for LangChain agents. Since you currently have a DeepSeek key, it will be the primary active key, with placeholders for other major providers:
  ```env
  # .env / .env.example
  DEEPSEEK_API_KEY=your_deepseek_api_key_here
  OPENAI_API_KEY=your_openai_api_key_here
  ANTHROPIC_API_KEY=your_anthropic_api_key_here
  GOOGLE_API_KEY=your_google_api_key_here
  ```
- **Global UI / Setup Plan**: 
  - Initialize the React app.
  - Set up a standard **Dashboard / Overview Page**: High-level progress tracker through the SLR pipeline, navigation sidebar, and status cards displaying the total number of papers per database.

### 2. Phase 1: Context & Data Ingestion
- **Agent / Process**: 
  - **Highlighting Agent (`agents/keyword_highlighter.py`)**: Invoked whenever the Context Configuration is submitted or updated. Utilizing LangChain, it parses complex Boolean keyword strings and generates deterministic matching functions/Regex. These compiled rules are appended to `metadata.json`.
  - **Data Parsers**: Implement parsers to normalize exports (RIS/CSV) into uniform JSON format.
  - **Combining Files**: If multiple files are uploaded to the same database, combine them into a single JSON file for that database.
  - **Indexing**: Upon ingestion, index each paper sequentially per database (e.g., `IEEE-001`, `ACM-042`).
  - Save the raw uniform JSON files in `data/01_raw_paper_list/`.
- **Web UI Pages Plan**:
  - **Database Management Page**: A dedicated page to view the list of configured data sources (Default: **IEEE Xplore, Scopus, Web of Science, ACM Digital Library**). Users can add custom databases. This list is saved to `context/metadata.json` and populates the upload dropdowns dynamically.
  - **LLM Agent Configuration Page**: A dedicated page to define and map which base LLM (provider and model, e.g., DeepSeek vs OpenAI) should be used for *each specific agent* (e.g., Highlighting Agent, Screening Agent). This mapping is saved to `context/metadata.json` so the backend dynamically routes LangChain calls to the correct provider.
  - **Context Configuration Page**: Web form to input global SLR metadata: Title, Research Questions, Keyword Strings, and structured Inclusion/Exclusion criteria. Saves data to `context/metadata.json` and triggers the Highlighting Agent.
  - **Data Ingestion (Upload) Page**: File dropzone interface where users select a target database and upload multiple files simultaneously. Displays a dynamic table of currently ingested databases, showing paper counts and index ranges.

### 3. Phase 2: Deduplication System
- **Agent / Process**: Handled by `agents/deduplication.py`.
  - Implement inter-database deduplication enforcing priority (e.g., IEEE -> ACM -> Scopus -> Web of Science).
  - Generate a Deduplication Matrix/Traceability Report detailing exactly how many duplicates were found per database and against which source.
  - Save the final deduplicated dataset into a new process folder: `data/02_deduplication/`.
- **Web UI Pages Plan**:
  - **Deduplication Review Page**:
    - **Metrics View**: Displays the Deduplication Matrix/Traceability Report.
    - **Review List**: A tabular view of all removed duplicates (showing `index`, `title`, `source`, and the "original paper" it matched). Includes a "Restore" button on each row.

### 4. Phase 3: Screening Interface & LLM Agent
- **Agent / Process**: Handled by `agents/abstract_title_screening.py` (Powered by LangChain).
  - Agent compares title, abstract, and keywords against criteria.
  - Generates reasoning and a suggested label (Include/Exclude/Maybe) using standard LangChain output parsers.
  - Save screening progress and final decisions in `data/03_abstract_title_screening/`.
- **Web UI Pages Plan**:
  - **Abstract & Title Screening Page**:
    - **Side-by-Side Split View Layout**: Left Panel shows `index`, `Title`, `Abstract`, `Year`, and **`Keywords`**. Right Panel shows Inclusion/Exclusion Criteria.
    - **Keyword Highlighting**: Dynamically highlights matching text using the deterministic regex compiled by the Highlighting Agent.
    - **Action Area**: Read-only text area for LLM reasoning, text area for User comment, and three action buttons: `[Include]`, `[Exclude]`, `[Maybe]`.
    - **Navigation**: "Next Paper" and "Previous Paper" buttons.
  - **Screened Papers Review Page**:
    - **List View**: Displays all screened papers with columns for Title, Author, Year, Abstract, Label, LLM Reasoning, User Comment.
    - **Color Coding**: Row is tinted based on the label (Green for Include, Red for Exclude, Yellow for Maybe).
    - **Inline Editing**: Quick action buttons to change the label seamlessly.

## Verification Plan
- **Manual Verification**
  - Verify data imports correctly from RIS/CSV exports.
  - Verify the LangChain Highlighting Agent properly parses Boolean keyword strings.
  - Visually inspect the deduplication matrix.
  - Perform a dry-run of the screening interface using the LangChain DeepSeek agent to verify label suggestions and inline editing.
